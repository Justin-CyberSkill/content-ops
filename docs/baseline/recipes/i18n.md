# Recipe: i18n with next-intl

For a UI in more than one language. Record it in `docs/decisions.md` when you add it.

## Rules

- The language is the first URL segment (`/vi/orders`), so each screen prerenders per language and links keep it.
- A cookie (`NEXT_LOCALE`) remembers the last choice. Ignore `Accept-Language`, so everyone starts in the default language.
- `en.json` types the keys: a missing or misspelled key fails `pnpm typecheck`.
- Every key goes into every message file in the same change.

## Files in `src/shared/i18n/`

| File                     | Holds                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `config.ts`              | `LOCALES`, `DEFAULT_LOCALE`, `LOCALE_COOKIE`, `DATE_LOCALES`, `isLocale()`, `Messages` (from `en.json`)        |
| `routing.ts`             | `defineRouting({ locales, defaultLocale, localePrefix: "always", localeCookie })`                              |
| `navigation.ts`          | `Link`, `redirect`, `usePathname`, `useRouter` from `createNavigation(routing)`; use them, not `next/link`     |
| `request.ts`             | `getRequestConfig`: locale from `next/root-params`, falling back to the cookie; loads `messages/<locale>.json` |
| `app-config.d.ts`        | `declare module "next-intl" { interface AppConfig { Locale; Messages } }`                                      |
| `messages/<locale>.json` | words, nested by view, plus `common`                                                                           |
| `testing.tsx`            | `renderWithIntl(ui)`: Testing Library's `render` inside `NextIntlClientProvider` with English                  |

## Wiring

- `next.config.ts`: wrap with `createNextIntlPlugin("./src/shared/i18n/request.ts")`; redirect `/:locale(vi|en)` to the first screen.
- Routes move under `src/app/[locale]/`. Its layout reads the locale from `next/root-params`, calls `notFound()` for an unknown one, sets `<html lang>`, wraps children in `NextIntlClientProvider`, and exports `generateStaticParams` over `LOCALES`.
- `src/proxy.ts`: delete `accept-language`, then run `createMiddleware(routing)`, after any auth redirect. Match all but `api`, `_next`, `_vercel` and files with a dot.
- `vitest.config.ts`: `server: { deps: { inline: ["next-intl"] } }` under `test`.

## Writing

- `getTranslations("view")` in async server code and `generateMetadata`; `useTranslations()` in client and sync components.
- Server Actions return translated text in `{ error }`. Zod schema factories take `t`.
- Dates: `Intl.DateTimeFormat(DATE_LOCALES[locale], { timeZone })`. Use `en-GB` for English to keep day before month.

## Pitfalls

- `proxy.ts` imports `@/shared/i18n/config` and `@/shared/i18n/routing` directly: the index pulls in `request.ts`, which proxy can't load.
- Server Actions can't read the `[locale]` segment, so `request.ts` falls back to the cookie the middleware keeps in step.
